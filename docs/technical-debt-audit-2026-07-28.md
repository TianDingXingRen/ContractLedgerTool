# 软件技术债务与缺陷审查记录

审查日期：2026-07-28（2026-07-29 完成第五轮复验）
审查范围：应用启动与网络边界、Flask 路由、文档导入与生成、SQLite
备份恢复、运行时清理、采购并发、文件事务、依赖与 CI 质量门禁。

## 结论

本轮识别的高风险和主要中风险问题已修复，并补充了针对性回归测试。
全量非性能测试 595 项通过，性能测试独立复验 4 项通过；总覆盖率 79.68%，
关键模块覆盖率预算通过；架构检查、Ruff、Office 兼容检查、JavaScript
语法检查及 CSS 可重复构建均通过。

Python 运行依赖和 npm 依赖均未发现已知漏洞。运行锁与开发锁已改为带
SHA-256 哈希的可复现锁文件，并通过 `pip --require-hashes --dry-run` 验证。

## 已修复问题

### 网络与 Web 安全

- 增加 `TRUSTED_HOSTS`，拒绝任意 Host 头；修复 Host 在 URL 适配器创建前
  被拒绝时，通用错误页再次调用 `url_for()` 导致二次异常的问题。
- 将所有已识别的“生成、导出、归档”副作用操作从 GET 改为带 CSRF 的
  POST；合同 PDF 的 GET 只下载已生成文件，不再触发转换。
- 非回环监听必须显式启用、关闭调试模式、设置至少 16 位访问令牌，并提供
  存在的 TLS 证书和私钥；远程会话 Cookie 标记为 Secure。
- 对安全请求增加 HSTS；修复非法或为零的限流配置可能导致运行时异常的问题。

### 不可信文件处理

- DOCX、XLSX、PDF 报价、合同导入预览、模板字段识别和预览均移入
  `spawn` 子进程，设置执行超时和进程内存上限。
- Windows 使用 Job Object 限制进程内存并在句柄关闭时终止残留进程；
  POSIX 使用 `RLIMIT_AS`。
- 对 Excel 行列数、Word 表格和文本量、PDF 页数和 OCR 时间增加上限；
  Excel 使用只读模式，子进程异常保持业务 `ValueError` 语义。

### 数据完整性与文件事务

- 完整备份不再只执行 SQLite `quick_check`；同时校验应用必需表、台账和
  采购架构版本，并核对清单声明的版本。
- 发票附件在数据库登记失败时删除已写入文件，避免孤儿附件。
- 采购项目自动编号改为 `BEGIN IMMEDIATE` 事务内生成和插入，消除并发重复
  编号窗口。
- 清理任务分别使用上传和输出保留期，保护合同及未完成生成任务路径，递归
  清理 staging、recovery 和发票回收区，并保留需要人工关注的任务记录。
- 修复付款计划数量、澄清项目编号等畸形输入处理；修复自启动 PowerShell
  命令中的单引号转义。

### 供应链与可维护性

- Pillow 升级到 12.3.0，消除审计发现的已知漏洞。
- `requirements.lock` 与 `requirements-dev.lock` 使用精确版本和 SHA-256
  哈希；CI 和发布流程强制 `--require-hashes` 并执行 Python/npm 漏洞审计。
- 将付款、生产通知、模板、合同导入和采购路由按用例拆分；主蓝图只保留
  组合与注册职责，参数校验、业务编排、查询命令、文件解析和合同交接移入
  表单/服务层。采购域 44 个端点由精确路由契约测试锁定，路由层不再直接
  依赖采购存储模块。
- 将合同首页/编辑器、台账查询与导出、批量状态、回收站和更新路由从
  `contracts_bp.py` 迁出，17 个合同端点由精确契约测试锁定；新增路由通过
  服务层访问台账和 XLSX 导出，不再直接依赖基础设施模块。
- 将剩余的单份生成、生成预检和批量生成从 `contracts_bp.py` 迁出；主蓝图
  从 434 个逻辑行缩减为 19 个逻辑行，只负责组合子路由。PDF 输出、ZIP
  归档、台账补偿删除和采购状态回滚由服务层承接，合同生成 HTTP 层不再直接
  依赖台账存储、采购存储、PDF 转换器或 ZIP 实现。
- 批量归档只在 ZIP 成功关闭后返回；打开、写入或关闭失败会逆序撤销本批已
  生成合同、采购关联及输出文件。新增会话失效、模板缺失/损坏、非法源路径、
  分类错误、PDF 成功/失败和四类生成事务异常回归测试。
- 修复非标准报价映射对三位以上小数税率静默截断的问题，并拒绝非法、负数
  或超出表头范围的列映射，避免错误列被当作有效报价数据导入。
- 质量门禁不再复用固定 pytest 临时目录；每次运行使用唯一且自动清理的
  临时根目录，避免并发执行或沙箱/非沙箱切换导致权限污染。覆盖率报告明确
  排除构建临时产物，防止复制的安装器脚本稀释生产代码指标。
- 新增 Host、TLS、GET 副作用、隔离进程、备份有效性、限流、附件回滚、
  嵌套清理、历史保留、并发编号和自启动转义回归测试。

## 剩余非阻断债务

- 局域网模式虽然已强制 TLS、令牌和关闭调试，但仍使用 Werkzeug 内置服务；
  如需长期、多用户或跨网段部署，应迁移到经过运维加固的生产 WSGI 服务或
  反向代理，并配置证书轮换、访问日志和网络 ACL。
- 当前环境未检测到真实 PDF 转换器，因此只完成了转换逻辑和 Office 兼容
  检查；发布前应在安装 LibreOffice 或 Microsoft Word 的目标机上做一次真实
  DOCX→PDF 冒烟测试。
- `settings_bp.py` 和 `invoices_bp.py` 仍是偏重的遗留路由；合同下载和
  工作区子路由也仍保留少量基础设施直连。采购域中的比价算法与报价服务虽然
  已从 HTTP 层隔离，但服务内部仍较密集。后续应继续按用例拆分，优先覆盖
  异常、并发与恢复分支。
- 文件系统移动与 SQLite 提交仍无法组成真正的原子事务；现有 staging、
  补偿删除和恢复日志只能降低风险。若需要更强保证，应引入可重放的持久化
  作业状态机，并让恢复过程具备幂等校验和启动时自动续作能力。
- Tailwind 构建提示 Browserslist 数据可更新。该提示不影响当前构建，
  更新时应单独提交并重新执行 UI 回归。
- 本轮未执行正式安装包签名、目标机安装/卸载和真实证书远程访问测试；这些
  属于发布环境验证，不应由单元测试结果替代。
