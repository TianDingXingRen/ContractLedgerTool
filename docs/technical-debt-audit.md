# 技术债与 BUG 审计（2026-08-11 复验）

## 范围与结论

本次审计覆盖 Flask 路由与安全钩子、SQLite schema/迁移/事务、合同与付款、采购工作台、DOCX/PDF/XLSX 文件生命周期、备份恢复、安装升级、运行时配置和主要前端状态流。

2026-07-21 首轮发现的 P0、P1 以及与合同/付款/文件生命周期相邻的 P2 已修复并增加回归测试。2026-08-11 复验又修复了依赖审计和架构门禁漏检：运行锁中的 `cryptography` 升级到 50.0.0，前端构建链中的 `nanoid`、`postcss` 升级到无已知漏洞版本；架构检查覆盖 160 个生产模块，并为既有超限模块启用只减不增的预算。下方保留仍需分阶段处理的非安全类债务。

## 剩余非安全技术债

### TD-01（P2）大型协调模块边界仍偏宽

- 证据：`ledger_store/__init__.py`、`services/handover_service.py`、`routes/settings_bp.py`、`routes/invoices_bp.py`、`excel_bill_service.py`、`services/project_document_service.py` 和 `xlsx_exporter.py` 仍同时承担多个用例或基础设施职责。`routes/contracts_bp.py` 与 `routes/procurement_bp.py` 已缩减为组合层，不再列为当前大型模块。
- 影响：小改动需要较大回归面，事务边界和文件生命周期规则较难局部推理。
- 建议：按“查询/命令”“上传/生成/下载”“备份创建/校验/恢复”继续拆分，并保持当前 facade 作为兼容层。

### TD-02（P3）合同全文搜索随数据量线性增长

- 证据：`ledger_store/list_queries.py::list_contracts` 对多个字段、`values_json` 和付款原文使用前导 `%` 的 `LIKE`，并包含关联子查询。
- 影响：当前 1 万级性能门禁可接受，但更大台账或长原文会放大 CPU 和 I/O。
- 建议：在数据规模达到门槛后引入 SQLite FTS5 搜索表及增量同步触发器，保留现有精确状态索引。

### TD-03（P3）Excel 单据合同选择存在预加载热点

- 证据：`excel_bill_service.py::get_contracts_for_selection` 最多读取 500 份合同并逐份提取采购标的。
- 影响：模板字段较多时，首次打开 Excel 单据页会产生不必要的解析和内存占用。
- 建议：选择列表仅返回合同摘要，用户选中合同后再调用现有明细接口加载列和行。

### TD-04（已关闭）完整备份的 Web 上传与生成容量契约

- 状态：完整备份上传已使用独立请求上限，并在解析请求体前完成 CSRF 与限流校验。
- 容量：生成端与恢复端共享成员数、单文件、解压总量和压缩包大小限制；生成时在写入成员前执行容量预算。
- 回归：覆盖超限请求、上传中断清理、生成包自检失败清理及写入前拒绝超限成员。

### TD-05（P3）采购生成文件缺少跨进程的持久化作业日志

- 证据：`services/procurement_file_service.py::save_generated` 已处理普通异常并清理文件，但进程在文件替换与数据库登记之间被强制终止时，可能留下未登记文件。
- 影响：不会损坏项目记录，但可能产生占用磁盘的孤立文件。
- 建议：后续复用合同生成作业日志模式，或在启动维护中对采购目录执行“登记记录—文件哈希”双向对账。

### TD-06（P3）大型交接导出仍会聚合完整结果集

- 证据：`services/handover_service.py` 的交接数据组装和 `xlsx_exporter.py` 的部分普通工作簿路径会在内存中保留完整列表。
- 影响：超大台账导出时峰值内存随记录数增长。
- 建议：将所有清单切换为数据库游标分批读取与 write-only 工作簿，并为全量导出增加可观测的进度和取消机制。

### TD-07（P3）浏览器公式中间运算仍使用二进制浮点

- 证据：前端公式引擎按后端规则处理输入、依赖顺序和 HALF_UP 最终格式化，并拒绝超过可靠有效位的预览，但中间四则运算仍基于 JavaScript `Number`；后端以 `Decimal` 为权威结果。
- 影响：极端高位抵消、长除法链或舍入中点附近的构造值仍可能在预览与最终文档间出现末位差异；生成前后端会重新计算，因此持久化结果不受浏览器预览支配。
- 建议：后续引入经过审计的十进制定点库，或将公式预览迁移为后端批量计算接口，并复用同一组跨语言测试向量。

## 验证策略

- 专项测试覆盖合同导入、迁移、重复提交/并发、文件与数据库失败、崩溃恢复、Office 包安全、金额边界、安装器目录保护、备份恢复、模板原子恢复、XLSX 公式注入和采购文件登记回滚。
- 最终交付以 `scripts/quality_gate.py commit`、`scripts/quality_gate.py ci`、`git diff --check`、依赖锁检查及可用的依赖安全审计为准。
- 依赖升级后必须重新生成 CycloneDX SBOM；`tests/test_generate_sbom.py` 会验证仓库 SBOM 输入包含已修复的运行依赖版本。
